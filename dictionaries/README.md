# dictionaries/

Generated. Do not edit by hand.

One JSON file per vendor and category, `dictionaries/<vendor>/<slug>.json`, containing every readable OBJECT-TYPE the vendor's MIBs define under their enterprise prefix. `role: dictionary`, no `matchPatterns`. Kaleidoscope imports these disabled and uses them as the OID reference behind the profile editor and import wizard. They are never assigned to a device.

Regenerated automatically by the `recompile` GitHub workflow on every push to `main` that touches `mibs/`, `registry/`, or `tools/`. To regenerate locally:

```bash
cd tools && pnpm compile                      # from mibs/
cd tools && pnpm compile --mibs /path/to/mibs # from a MIB collection outside the repo
```

The compiler drives libsmi's `smidump` (native or through Docker, see the top-level README), one process per vendor directory, and groups objects by the compile-enabled prefix rows in `registry/sysobjectid.yaml`. Rows may name IETF subtrees as well as enterprise roots; `mibs/rfc/` is compiled first so the canonical module wins when a vendor bundles its own copy. Matching is octet-anchored and the shortest matching row wins, so a vendor's whole tree lands in one dictionary even when deeper rows exist for sysObjectID identity. Objects outside the row's prefix, objects that cannot be read (`not-accessible`, `accessible-for-notify`), and objects under prefixes with no registry row are dropped and counted.

Each OID entry carries `oid`, `name`, `metricKey`, `type` (`integer|string|gauge|counter|timeticks|oid`, resolved through textual conventions), `walk` (true for table columns; scalars carry the `.0` instance suffix so they can be polled as-is), `description` (first 200 characters), `enumMap` for enumerations, and when present `units`, `status` (only if not `current`), `module`, and `tc` (the textual convention the object was declared with).

`COMPILE-REPORT.md` in this directory is written on every run: counts, per-dictionary sources, enterprises with MIBs but no registry row, files libsmi crashed on, hung on, or produced runaway output for (each is isolated by bisection and skipped), and textual conventions that could not be resolved.

## History

- 2026-09-11: first generation with a copy of the monorepo's regex parser (17 files, 13,775 OIDs). That parser turned out to extract about 18% of the objects in its input.
- 2026-09-11, later: regenerated with libsmi 0.4.8. A first pass over a 14,391-file local mirror produced 20 dictionaries / 142,922 OIDs and showed that 1,102,053 further readable objects sit under 486 enterprises with no registry row, so coverage grows by adding rows and importing those vendors' directories. The 23 directories those 20 dictionaries came from were then committed under `mibs/` and the dictionaries regenerated from the repo alone: 20 dictionaries, 143,196 OIDs (Cisco 89,048; HP 29,245; Juniper 9,553), 44 s on 4 cores, 1 file skipped (`juniper/EX2500-BASE-MIB` crashes libsmi), 156 objects typed `string` for lack of a textual convention. The Cisco file is 45 MB (dropping descriptions would only get the total from 68 MB to 52 MB); GitHub's hard limit is 100 MB per file, so if Cisco keeps growing the dictionary will need splitting by module family.
- 2026-09-12, batch 2: 107 registry rows added for MSP-relevant vendors (switches, firewalls, wireless, servers, storage, UPS/PDU, printers, VoIP, appliances) and their 111 source directories imported. Result: 127 dictionaries, 529,016 OIDs, 136 s on 4 cores; 2 crashes, 1 runaway and 45 unparseable files skipped (all listed in the report), 504 objects typed `string`. Same-named modules from different vendors (D-Link and Nortel both ship an AAC-MIB) are no longer dropped; OIDs are deduped per dictionary instead. Left out deliberately for now: carrier/optical/industrial vendors (Ekinops, CTC, Dasan, ADVA, RAD, ZTE, Ciena, Infinera, Calix, Raisecom, Hirschmann, LANCOM, Nokia SR, IBM RackSwitch, A10) — about 380 roots and 600k objects in the local mirror.
- 2026-09-12, batch 3 (IoT, printers, UPS): registry rows may now point at standards-track subtrees, and `mibs/rfc/` is compiled as a group, so `mib-ietf-printer` (Printer-MIB, 175 OIDs), `mib-ietf-ups` (UPS-MIB, 55) and `mib-ietf-server` (HOST-RESOURCES-MIB, 61) exist; these are what printers and UPS cards are polled through regardless of vendor. 109 vendor rows added for UPS and DC power (MGE, Best Power, GE, Gamatronic, Alpha, CE+T, Eltek Valere, Delta Energy Systems, Emerson Energy Systems, PowerShield, Next UPS), PDUs (Eaton ePDU, Enlogic, Powertek, Raritan already present, BayTech, Schleifenbauer, Bachmann, Gude, NETIO, Synaccess), environmental sensors and DCIM (NetBotz, Kentix, Comet, AVTECH, NTI, NetPing, ServersCheck, Didactum, Vutlan, Chatsworth, RLE, Carel, Siemens automation), industrial switches (RUGGEDCOM, MICROSENS, Korenix, Phoenix Contact, Westermo, EtherWAN, Advantech, Red Lion, Sixnet), cameras, intercoms, access control, clocks, console servers, and host agents (UCD-SNMP, FreeBSD, OpenBSD); 83 source directories imported. Result: 237 dictionaries, 579,862 OIDs, 164 s on 4 cores; 2 crashes, 1 runaway and 53 unparseable files skipped, 570 objects typed `string`. Vendor labels are made distinct where one vendor owns several roots in the same category (Eaton / Eaton DC Power / Eaton ePDU, Vertiv / Vertiv DCS, NetBotz / NetBotz v5) because one dictionary carries one `vendorOidPrefix`. The public mirror has no vendor MIBs for Konica Minolta, Sharp, Epson, Toshiba TEC, or Fuji Xerox printers.

The monorepo's older `compiled-mibs.json` (55,919 OIDs) was never carried over. Its compiler matched enterprise prefixes as plain string prefixes, so `1.3.6.1.4.1.23` (Novell) swallowed `1.3.6.1.4.1.2356` (Lancom) and `1.3.6.1.4.1.2` (IBM) landed in Sophos. Roughly 75% of its OIDs were under the wrong vendor.
